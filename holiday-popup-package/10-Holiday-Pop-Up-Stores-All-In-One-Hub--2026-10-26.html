What moves when a store changes

For Jordan, Juliana and Darren. Three kinds of change, three different owners.

Change a model photo, banner or link: about 10 seconds

  1. Open the club's Fastr page and the HTML component (Top or Bottom block).
  2. Find the image URL or link you want to change. Every photo on the page is a plain https address.
  3. Paste the new address over the old one. Keep the width and height numbers next to it.
  4. Save. Open the page in a second browser to check, because Fastr can keep showing a stale version after save.

Or rebuild from Airtable

  1. Change the field in the Team Sales Master base, table Pop-up Store Product (tblNWQqlb5AMoyQoM).
  2. Ask Components to rebuild the club's Top and Bottom paste files. The build reads Airtable and the contract, so nothing is typed twice.
  3. Paste the new files into the same two Fastr components.

Change a product in the grid: no HTML at all

  1. The grid is the native DX contract component. It reads the club's TPS contract.
  2. Gabby changes the contract, or DX edits the component in the DX tools.
  3. The page updates on its own. No paste, no rebuild, no Excel export.
Why the grid is native. In TPS and Player Pass the contract items are virtual products. They cannot link to normal Soccer.com product pages with club pricing, so a hand-built grid would always drift. The native widget is the one source of truth.
Two Fastr bugs to design around. A saved component can keep showing the old version for a while (check in a second browser). There is no edit lock, so two people editing one component overwrite each other. Agree who is in which component before you start.
