Slots: a pocket inside a component (how the Hero Words slot works)

A slot is an empty pocket inside a component. The frame stays the same; you drop different content into the pocket.

The hero is the example. One banner, and its Words slot can hold big campaign lettering, an everyday headline with copy and a button, or nothing at all for a photo-only hero.

Using the hero:

  • One text block in the Words slot, unless you mean to stack more.
  • Set Brand on each piece separately: the hero, the text inside it, and the button inside that.
  • Show or hide a whole text block with the eye in the Layers panel.
  • Leave the slot empty for a photo-only layout, where that layout allows it.

When a slot is the right tool:

  • Cards: a product, an offer or editorial content inside the same card.
  • Drawers and pop-ups: a form, a confirmation or detail inside the same container.
  • Promo banners: a different campaign layout without rebuilding the banner.
  • Page sections: one section wrapper holding different content.

When it is not, keep it simple:

  • Different words: type them in the text field.
  • Show or hide one thing: the on/off toggle.
  • Swap one icon: pick a different icon.
  • Brand, size or state: choose the variant.

Rule of thumb: a slot changes what is inside, not just a label, and not just turning something off.

Why it matters for the build: a filled slot tells the builder exactly which tested piece goes inside, so nothing is guessed.

Images and speed rules (plus the Flip-book Hero photo rule & Photo Sizer preset)

Images and speed (every component, ruled 20 Oct 2026):

  1. Every photo carries width and height.
  2. Smaller copies for bucket photos: Every photo that comes from the bucket offers smaller copies for phones and tablets (about 480 and 960 wide beside the full file, named --w480.jpg and --w960.jpg), because the host ignores a width parameter on bucket photos. The agent makes the copies; the designer uploads them under the names the code expects (and the image error handler strips srcset first so a missing smaller copy falls back to the full photo before hiding anything, alongside a preconnect line for imagehandler.net). Product pictures from the image service take a width and need no copies.
  3. First photo high priority: The first photo a visitor sees in a block is marked high priority. One per block, never more.
  4. No lazy loading: Every photo loads eagerly.
  5. Measure before and after with PageSpeed: Measure before and after with PageSpeed on the component preview and write the two scores in the handoff. Know that the preview carries the CMS embed delay (about 0.8s on phones before the first image can start), so mobile scores on the preview are capped; judge the page on the live template, not the preview.

Flip-book hero photo rule (ruled 20 Oct 2026): For the flip-book hero, each photo fills half the screen from edge to edge at a fixed height, so phones show a tall, narrow slice of it. Deliver photos that survive that:

  • Keep the subject inside the middle third of the frame, and above the bottom 40 percent.
  • Keep faces away from the centre of the pair, where the headline and button sit.
  • If the photo cannot be framed that way, deliver a second tall crop for phones (about 1 wide to 3 tall) and tell the agent; the hero can show the tall crop on phones and the full photo on desktop.
  • Photo Sizer preset link: Size your photo using the flip-book hero preset in Photo Sizer, which previews all four frame shapes at once (phone half 195 x 560, tablet half 384 x 680, desktop half 720 x 808, wide 960 x 808, with the centred crop set 30 percent from the top) and exports the three widths (480, 960, and full) so you see before upload whether the subject survives the phone slice.

Reserved heights in plain words (what the number is, where it comes from, and what wrong looks like)
  • What the number is: The pixel space the page keeps clear before your block finishes loading, at three screen widths: Mobile (measured at 390px wide), 640px and up (measured at 640px wide), and 1024px and up (measured at 1024px wide).
  • Where it comes from: The agent measures the rendered block with the real fonts loaded at the narrow edge of each width range and writes the three numbers in order in the header comment at the very top of your HTML file (and you can also see each component's standard heights on the Sports Endeavors Marketing Code Library).
  • What wrong looks like: If the reserved height is too short or missing, the rest of the page jumps down as your block loads (or the bottom of your block gets clipped). If the reserved height is too tall, an empty blank gap sits underneath your block.

Step-by-step: from Downloads to Fastr (one action per line)

1. Find the one FINAL file in your Downloads folder:

  1. Look in your Mac's Downloads folder for the single final file the agent saved for you.
  2. Check that the filename matches the exact name the agent wrote in chat, carrying the page name, the word FINAL, the date, and the time (for example: wss-sale-page--FINAL--2026-10-20-1035.html).
  3. Never click the chat Download button, because chat downloads save generic names (such as _1 and _2) that make it impossible to tell which copy is current. (Only a file that has passed Fable's check carries FINAL in its name; the copy in the build folder keeps its normal name without FINAL.)

2. Never copy code from a chat window:

  1. Never highlight or copy code out of a chat window.
  2. Chat windows cut long code off and change straight quotes into curly quotes that break the page.
  3. Only ever copy code from the saved FINAL file on your Mac.

3. Photo check before the paste (open the FINAL file in a browser first):

  1. Before you open a code editor or paste into Fastr, right-click the FINAL file in your Downloads folder, click Open With, and pick your web browser (such as Safari or Chrome).
  2. Scroll from top to bottom and check that every photo on the page shows cleanly.
  3. If you see a dark blank box or a broken-image icon anywhere, stop and tell the agent (do not paste into Fastr until the photo is fixed). If every photo on the page is missing, not just one, that is the image host refusing your Mac rather than the file; tell the agent before pasting.

4. Open the FINAL file in a code editor:

  1. Once every photo shows cleanly, go back to Finder and open the FINAL file in a code editor (do not copy code out of the browser window).
  2. Visual Studio Code (Top pick for a designer who has never coded): Free, simple, opens any file, and needs no account (code.visualstudio.com). Open Visual Studio Code, click File in the top menu bar, click Open, and pick the FINAL file in your Downloads folder.
  3. Cursor (Second pick, if you want AI help while you look at code): Free plan, same layout as Visual Studio Code, and Alex already uses it (cursor.com). Open Cursor, click File in the top menu bar, click Open, and pick the FINAL file in your Downloads folder.
  4. Antigravity IDE (Google, free): Free code editor from Google (antigravity.google). Open Antigravity IDE, click File in the top menu bar, click Open, and pick the FINAL file in your Downloads folder.
  5. BBEdit (If you already have it; free mode is enough): (barebones.com/products/bbedit). Open BBEdit (or any other code editor you already use, such as Dreamweaver or Sublime), click File in the top menu bar, click Open, and pick the FINAL file in your Downloads folder.
  6. TextEdit in plain text mode (Last resort if you have nothing to install): Open TextEdit, click Format in the top menu bar, click Make Plain Text first (rich text mode breaks the quotes), and then click File, click Open, and pick the FINAL file in your Downloads folder.
  7. What NOT to use: Never open or copy code in Word, Pages, Notes, TextEdit in rich text mode, a web browser, or Figma.

5. Select all and copy, and check that the whole file was selected:

  1. Click once inside the code window.
  2. Press Command A on your keyboard to select everything from the very first line to the very last line.
  3. Scroll all the way to the bottom of the file and check that the last line is highlighted and matches the closing tag the agent named in chat.
  4. Press Command C on your keyboard to copy the selected code.
  5. Check your file and create your ClickUp share link in Code Share (checked 20 Oct 2026): Open Code Share in The Tunnel (behind the Tunnel password), click + Paste & share a new file, paste the copied code, and click Create share link & copy (or Copy link for ClickUp). Code Share checks the line count, secrets, promo codes, and live colour contrast so you know nothing was cut off, and generates one self-contained share link for the ClickUp task's HTML Code row.

6. In Fastr: open the test page, open the HTML widget, click in the code box, select all, delete, paste, save:

  1. Open your own test page in Fastr CMS.
  2. Open the HTML widget for your component.
  3. Click once inside the code box.
  4. Press Command A on your keyboard to select all the existing code in the box.
  5. Press Delete on your keyboard so the code box is empty.
  6. Press Command V on your keyboard to paste your new code.
  7. Click Save.

7. Check that it landed (and what Fastr's stale cache looks like):

  1. View your Fastr test page and confirm the page shows the updated block.
  2. If it still looks like the old version, test in a second browser before reporting a bug (Fastr's cache can hold onto an older version after saving).
Browser 1 (where you just clicked Save: stale cache) Browser 2 (fresh check in a second browser)
You clicked Save in Fastr, refreshed the test page, and it still shows the old headline, old photo, or old layout from before your paste. You paste the exact same test page URL into a second browser (for example Safari if you work in Chrome) and the new headline, new photo, and new layout appear immediately.
What this means: Your paste worked. Browser 1 is holding onto Fastr's cached copy. Do not re-paste or file a bug if Browser 2 shows the new build. If Browser 2 ALSO shows the old version: Then the save genuinely did not take, or the wrong widget was edited. Re-check the HTML widget box and click Save again.

8. If Downloads has several similar files:

  1. Look at the date and time at the end of the filename and use the newest FINAL file.
  2. If two files have the same time, or you are unsure which file is right, stop and ask the agent which one to use.
  3. Move older copies out of Downloads, or rename them with zz_ in front so you never pick an old file by mistake.

What you can change safely later vs. what needs Components (and the two Fastr bugs to watch for)
Safe to change yourself (no rebuild needed) Needs Components (ask for a rebuild) The two Fastr CMS bugs to watch for
  • A word or headline (if the line count stays the same).
  • A link address taken from the link book (SITE-LINKS).
  • A photo filename that is already uploaded on the image host (at the exact same crop and dimensions).
  • Anything inside the <style> block (colours, fonts, spacing, breakpoints).
  • Any of the 3 reserved heights (or text changes that wrap onto extra lines and change the height).
  • Adding, removing, or reordering a block or card.
  • 1. No edit lock: Fastr does not warn you if someone else has the same component open; the second person to click Save silently overwrites the first. Rule: one editor per component; check nobody else is in it before you open it.
  • 2. Stale cache after save: Fastr can keep showing the old version in your browser after you click Save. Rule: always check the page in a second browser before re-pasting or reporting a bug.

Tell Components after any change in Fastr: After any change made directly in Fastr, tell Components what you changed (one message is enough), so the file on the Mac and in the library is updated to match. Otherwise the change is lost at the next rebuild.

5 rules when using ChatGPT, Gemini, or Copilot

1. Turn off model training first: Disable "Improve the model for everyone" in settings before uploading briefs or Figma frames.
2. Never paste secrets or feeds: Keep passwords, API keys, wholesale product feeds, and embargoed packs out of AI chats.

File-weight ceilings (ruled 16 Oct 2026): Full-width desktop heroes up to 300 KB; every other photo under 200 KB; transparent cutouts under 100 KB; crests and logos under 20 KB.

Images and speed (ruled 20 Oct 2026): (1) Every photo carries width and height. (2) Every bucket photo offers smaller copies for phones and tablets (about 480 and 960 wide beside the full file, named --w480.jpg and --w960.jpg), because the host ignores a width parameter on bucket photos; the agent makes the copies and the designer uploads them under the names the code expects (product pictures from the image service take a width and need no copies). (3) The first photo a visitor sees in a block is marked high priority (one per block, never more). (4) No lazy loading. (5) Measure before and after with PageSpeed on the component preview and write the two scores in the handoff (knowing the preview carries the ~0.8s CMS embed delay on phones before the first image can start, so judge mobile on the live template).

Flip-book hero photo rule & Photo Sizer preset (ruled 20 Oct 2026): Each photo fills half the screen from edge to edge at a fixed height, so phones show a tall, narrow slice of it. Keep the subject inside the middle third of the frame and above the bottom 40 percent, and keep faces away from the centre of the pair where the headline and button sit (or deliver a second tall 1:3 crop for phones and tell the agent). Size your photo in the flip-book hero preset in Photo Sizer to preview all four crops at once (phone half 195 x 560, tablet half 384 x 680, desktop half 720 x 808, wide 960 x 808, centred crop 30 percent from the top) and export the three widths (480, 960, full).

Sharing HTML code on ClickUp (Code Share)

Instead of pasting thousands of lines of raw code into a ClickUp comment or field, open Code Share, click + Paste & share a new file, paste your complete HTML file, and click Create share link & copy.

Paste that single link into the ClickUp task's HTML Code row (and still save the HTML file in your Box folder). Anyone who opens your link can preview the block, check the 3 measured heights, or copy the full HTML in one click.

Products, prices & stock

The requester supplies an ordered Tunnel Product picks link. You never choose products, open the raw product feed, or type SKUs by hand.

Ask on the ClickUp task to get verified store URLs, names, and images from the feed. If a block displays prices, flag it on the task so prices are re-checked before go-live and at the 7-day read.

Hero video rules

Start from the existing Hero Video component inside a Fastr HTML block (never Fastr's native video widget). Supply a mobile video, desktop video, and poster image for each. Video plays muted with a visible pause button, shows the poster image under reduced motion, and includes captions if anyone speaks.

Never

  • Paste anything onto a live store page.
  • Copy code out of a chat window or click the chat Download button (only ever open the newest FINAL file from Downloads in a code editor).
  • Edit repository files or canon code directly.
  • Mix brands (Soccer.com, WSS, 431, Team Soccer, Soccer Master, Partners).
  • Invent a URL, file name, SKU, or block ID.
  • Move a Figma frame after marking it final (comment on the task instead).
  • Show an untested promo code on a public test page.
  • Paste passwords, API keys, wholesale feeds, or embargoed files into AI.
  • Start work from an email or chat message without a ClickUp task.
