02 · Step 1: Pick & Prep (5 mins) Code Library · Photo Sizer · Link Book

1. Gather your starting code, photos, and links.

Before you open AI or Fastr, lock these three inputs in your Box folder so nothing is guessed during the build.

Input 01 · The Starting HTML

Pull from the SE Code Library

  • Filter to WorldSoccerShop Open the Marketing Code Library and preview the component at Desktop, Tablet, and Phone widths.
  • Download the reference HTML Click Download HTML (or copy the file from the read-only GitHub repo into your working folder).
  • Check the 3 standard heights Note the component's baseline Mobile (390px), Tablet (640px+), and Desktop (1024px+) pixel heights.
Input 02 · Photos & Speed

Crop in Photo Sizer first

  • Weight ceilings (JPG only, never WebP) Full-width desktop heroes up to 300 KB. Every other photo under 200 KB. Logos under 20 KB.
  • Export the 3 responsive widths Bucket photos need 480px (--w480.jpg), 960px (--w960.jpg), and full width because the image host ignores width parameters on bucket files.
  • Flip-book hero framing rule Keep subjects in the middle third and faces away from the centre headline. Use the Flip-Book Hero preset in Photo Sizer to check all 4 crops at once.
Input 03 · Verified URLs

Link Book & Tunnel picks only

  • Every page link from SITE-LINKS Take every destination URL from the Link Book in Box. If a link is missing, ask Components so it gets added the same day.
  • Products from Tunnel picks The requester supplies a Tunnel Product picks link. Never type SKUs or prices by hand.
  • Mask unreleased promo codes Test pages are public. Use PROMO-CODE-HERE until the requester's cart test passes.

03 · Step 2: Adapt with AI (8 mins) Step Zero Prompt · What Changes vs. What Stays Locked

2. Give your AI the Step Zero rules and your starting file.

Before asking Claude, Cursor, or ChatGPT to touch any code, paste the Step Zero prompt below so it knows what is off-limits.

What AI is allowed to change

Content, photos, and verified links only

  • 1. Headlines, body copy, and button labels Taken straight from your frozen Cabana 8 Figma frame, using HTML entities for any special characters.
  • 2. Image addresses and alt text Swapping in your uploaded imagehandler.net filenames (with --w480.jpg and --w960.jpg srcset copies) and descriptive alt text.
  • 3. Link Book URLs with target="_top" Every link opens in the parent window (target="_top") and carries no internal tracking parameters.
What AI must never touch

The layout engine, CSS scoping, and page shell

  • 1. Scoped CSS and Host-CSS Shield Never style html, body, :root, or bare *, and never use 100vh. Keep the component's doubled root ID shield intact so storefront CSS cannot shrink fonts.
  • 2. Image loading & fixed dimensions Every img tag keeps explicit width and height attributes. Images in the first screen load eagerly. On a page over 3,000 px tall, images below the first screen may use loading="lazy". The first hero is eager with fetchpriority="high".
  • 3. Complete, unbroken file output Never accept truncated code with "rest of code here" comments. Always require the full file from first line to closing tag.
Copy-Paste Step Zero Prompt for Designers 
You are helping me adapt a verified WorldSoccerShop Fastr CMS component. Follow these strict rules:
1. Start from the attached HTML file from the Sports Endeavors Marketing Code Library. Change the content (copy, links, image filenames), never the layout or CSS architecture.
2. Write a 5-line "Done means" list in plain words before coding (hero photo shows, buttons go to Link Book URLs, works at 390px phone width, no placeholders).
3. Keep all CSS scoped to the component root (never target html, body, :root, bare *, or 100vh). Keep explicit px font sizes and the doubled root ID selector shield.
4. Every link must come from SITE-LINKS (never invent a URL) and include target="_top". Use PROMO-CODE-HERE for any unreleased promo code.
5. Images in the first screen load eagerly. On a page over 3,000 px tall, images below the first screen may use loading="lazy". The first hero is eager with fetchpriority="high". Every image carries explicit width and height, and uses the uploaded --w480.jpg and --w960.jpg srcset copies for bucket photos.
6. Output the complete paste file, body only (one root div, no html, head or body tags), with zero working comments or Figma node numbers, and list the 3 measured heights (390px / 640px / 1024px) at the top. Fastr refuses any Reserved Height over 10000 px: say so and suggest 10000 or a split.

Reminder: Turn off "Improve the model for everyone" in AI settings before uploading briefs or Figma frames, and never paste passwords or product feeds.

04 · Step 3: Paste into Fastr (7 mins) Downloads → Browser Check → Code Editor → Fastr Reserves Space

3. How to paste into Fastr without losing a single character.

Chat windows cut long files off and turn straight quotes into curly quotes that break HTML. Follow this exact 3-step paste routine every time.

Step 3A · Before You Copy

Open the FINAL file in a browser first

  • 1. Find the FINAL file in Downloads Look for the exact filename with FINAL, date, and time (for example: wss-sale-page--FINAL--2026-10-20-1035.html). Never use the chat Download button.
  • 2. Right-click → Open With Safari or Chrome Scroll top to bottom on your Mac before touching Fastr.
  • 3. Stop if any photo is blank If you see a dark empty box or broken image icon, stop and tell the agent before pasting into Fastr.
Step 3B · Copy Cleanly

Open in VS Code, Cursor, or Antigravity

  • 1. File → Open in your code editor Open the FINAL file in Visual Studio Code, Cursor, Antigravity IDE, or BBEdit. Never use Word, Pages, Notes, or rich-text TextEdit.
  • 2. Press Command + A Select everything from line 1 to the bottom.
  • 3. Check the closing tag, then Command + C Scroll to the very last line to verify the closing tag is highlighted, then press Command + C.
Step 3C · In Fastr CMS

Paste, enter 3 heights, and copy "Reserves space"

  • 1. Command + A, Delete, Command + V In your Fastr HTML widget (Brand set to WorldSoccerShop), clear the old box completely, paste your new code, and enter the 3 heights (Mobile 390 / 640+ / 1024+, max 10000).
  • 2. Click Save, then pick "Reserves space" In the embed panel, always copy the Reserves space tab (never Standard) so the page holds the height before loading.
  • 3. Place on your test page only Paste that embed onto your own Fastr test page.
Talking baseline for Sacha (30 seconds)
"Two things save hours of debugging here: always open the FINAL file in Safari first to see that every photo loads, and always copy from a real code editor like VS Code or Cursor so a chat window never clips the bottom of your file."

Why Reserved Heights matter: without the 3 numbers in the Reserves space tab, the store page jumps downward while your block loads.

05 · Step 4: Edits & Platform Bugs (5 mins) What You Can Tweak vs. When to Ask Components

4. What you can edit yourself vs. what needs a rebuild.

Once your block is on your test page, small text or link swaps are safe to do in your code editor, while layout or style changes go back to Components.

Safe for Designers

Quick swaps you can make in your code editor

  • 1. A headline or word swap Safe to edit yourself as long as the text stays on the exact same number of lines at phone, tablet, and desktop widths.
  • 2. A destination URL Swapping one verified Link Book address for another inside an existing href attribute.
  • 3. An uploaded photo filename Swapping in a new imagehandler.net filename that is already uploaded at the exact same crop and dimensions (plus its --w480 and --w960 copies).
Send to Components

Changes that require a fresh build & height check

  • 1. Anything inside the <style> block Colours, font sizes, spacing, padding, or breakpoint rules.
  • 2. Anything that changes the 3 heights Adding extra lines of copy, taller images, or new rows that change the pixel height at 390px, 640px, or 1024px.
  • 3. Adding, removing, or reordering cards Changing the number of tiles, buttons, or sections in the component.
Watch Out in Fastr CMS

Two live platform bugs every designer hits

  • Bug 1: Stale cache after clicking Save Fastr often keeps showing your old version in the browser where you just clicked Save. Always paste your test page URL into a second browser (like Safari) before re-pasting or reporting a bug.
  • Bug 2: No edit lock on components Fastr does not warn you if someone else has the same component open. The second person to click Save overwrites the first. Check nobody else is in the component before opening it.
Talking baseline for Sacha (30 seconds)
"If you click Save in Fastr, refresh your test page, and still see the old headline, do not panic and do not re-paste five times. Open Safari and check the link there first. Nine times out of ten, Chrome is just holding onto Fastr's cached copy."

Important rule: If you make a small word or link swap in Fastr, send one quick message to Components so the master file on the Mac and in GitHub is updated to match.

06 · Step 5: Test & Hand In (5 mins) Responsively · Jam · Code Share · ClickUp

5. Five-minute quality check and ClickUp hand-in.

Never paste thousands of lines of raw HTML into a ClickUp comment. Use Code Share to generate one clean link for your task.

Check 01 · 5 Screen Widths

Verify in Responsively & record a Jam

  • 1. Check 360, 390, 768, 1024, and 1440 Open your Fastr test page in Responsively App. Confirm no bottom clipping, no horizontal scrollbars, and no layout jump on load.
  • 2. Check Safari on Mac Confirm fonts, images, and interactive tabs or lightboxes work cleanly.
  • 3. Record 1 Jam video Record desktop and mobile widths plus every interactive state (tabs, drawers, pop-ups).
Check 02 · Code Share Link

Turn your HTML file into 1 link

  • 1. Open Code Share in The Tunnel Click "+ Paste & share a new file" and paste your complete FINAL HTML file.
  • 2. Automatic pre-flight check Code Share checks your line count, scans for leaked secrets or promo codes, and verifies WCAG colour contrast automatically.
  • 3. Click "Create share link & copy" Paste that single link into the HTML Code field on your ClickUp task.
Check 03 · Move to UX Review

The 7 hand-in items (1 day before launch)

  • 1. Code Share link & Box file path In the HTML Code row and at the top of the page's Box folder.
  • 2. Preview sign-off, Figma & Test Page links Requester approval date, frozen Figma frame link, and Fastr test page URL.
  • 3. Jam link, 3 heights & Done-means check Jam video, the 3 heights (390 / 640 / 1024), and Pass / Fail / Not checked self-check.
