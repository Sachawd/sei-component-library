Individual logins for the hub: Cloudflare Access setup

One login gate in front of the site using Cloudflare Access email one-time codes. Same five steps for two separate accounts and owners.

No DNS change, push, or deploy before Monday 2 November and Sacha's word.

Prepared Friday 30 October 2026 at 12:45pm PT. No token, password, or allow list ever sits inside a page; the Cloudflare gate holds them in front of the site. Contrast measured: Ink (#303030) on Panel (#F5F5F5) is 12.1 to 1 (Pass); Body text (#4B4A48) on White (#FFFFFF) is 8.9 to 1 (Pass).

2. Five setup steps in Cloudflare Access (10 minutes)

Both owners follow the exact same five steps inside their own Cloudflare account.

Step Where to click in Cloudflare What to enter Time
Step 1 · Add proxied DNS record
  • Open Websites, pick your domain, and click DNS > Records.
  • Add a CNAME record for the hub subdomain (hub for hub.theory8.com on Sacha's account; the internal hub subdomain on the company account).
  • Turn Proxy status on (orange cloud) so Cloudflare sits in front of every request.
 2 mins
Step 2 · Create a Self-hosted Access app
  • In the left menu, open Zero Trust > Access > Applications.
  • Click Add an application and choose Self-hosted.
  • Give the application a plain name and set Session Duration to 24 hours or 1 week.
 2 mins
Step 3 · Protect the hostname and pick One-time pin
  • Under Application domain and Identity providers on the same screen.
  • Enter the subdomain (hub.theory8.com for Sacha; the company subdomain for Jason).
  • Keep One-time pin (OTP) enabled so Cloudflare emails a 6-digit login code to approved viewers with zero passwords to manage.
 2 mins
Step 4 · Add the Allow policy (email list)
  • On the Policies tab, name the policy Approved viewers and set Action to Allow.
  • Under Include, choose Emails and enter each viewer's email address.
  • The gate holds the allow list; never put email addresses or passwords inside the page code.
 2 mins
Step 5 · Add or remove a person in one place
  • Open Zero Trust > Access > Applications > Policies.
  • To remove a viewer, delete their email from the Cloudflare policy and delete their one line from the hub settings file.
 2 mins

3. How the hub reads the signed-in role

Components builds the settings file and role map on the Mac this weekend so viewer names leave the hub code.

Settings file

One settings file per hub

  • Holds the logo, colours, brand names, feed paths, the one-line privacy note, and the people list with roles.
  • Uses first names only (for example Sacha, Jordan, Courtney, Taj for all brands; Soccer.com-only and WorldSoccerShop-only viewers mapped to their store).
  • Removing a person from the hub view is deleting a single line in this file.
Role map and View-as switch

Header-driven role map

  • Cloudflare Access passes the signed-in email in the Cf-Access-Authenticated-User-Email request header.
  • Until the live gate is connected, the hub reads from a local sample role map.
  • Includes a "View as" switch for all-brand viewers so Sacha can preview a single-brand or client view before anyone else sees it.
